# Project working agreements

- Before preparing or publishing a release, query RepoPlane for the current memo with topic key `release-procedure-must-be-registered` and follow its latest revision. Do not reconstruct the release procedure from memory when RepoPlane is available.
- Treat release publication as gated: push the intended commit, require Windows and Linux CI success for that exact SHA, retain the unstripped artifact privately for diagnostics, strip only a copied public candidate, then verify that stripped candidate's embedded `--version`, functional MCP smoke, process-lifetime and concurrency regressions, format/architecture, size, and SHA-256 before creating the matching tag and GitHub release; publish the stripped candidate only when it is smaller and every gate passes.
- On Windows, keep the versioned release `BUILD_DIR` at the repository root and deliberately short (currently `r`) until the monolithic link is converted to response files. Even `build/r` can exceed the `CreateProcess` command-line limit once version flags are added, appearing as truncated missing paths.
- Use a current pinned Windows LLVM-MinGW x86-64 toolchain configured through an ignored local profile, with compatible Make utilities and zlib headers/libraries. Never reuse a `BUILD_DIR` after changing compiler, C/C++ runtime, sanitizer, or version flags: choose a fresh short root directory so incompatible objects cannot contaminate a release.
- While waiting for CI, poll at five-minute intervals and do not start unrelated speculative work.
- For local deployment beside `agent-tool.exe`, preserve an existing executable as `old_<target-stem>_<yyyyMMdd_HHmmss>.exe`, install the verified new binary, and compare SHA-256 hashes without terminating active Codex or MCP process trees.
- Treat `DeusData/codebase-memory-mcp` as the upstream reference, not as an automatically correct product policy for CodeGraph Light. Fetch and compare upstream before related work, but do not merge `upstream/main` wholesale or copy an upstream runtime/daemon/cohort behavior without explicit user approval and a path-level impact review. Selectively port only the commits or hunks needed for this product, preserving the reduced tool surface and local operating assumptions.
- Upstream synchronization is selective, not branch-wide. Parser, extraction, graph-quality, traversal, and store fixes may be ported after reviewing their complete commit diff plus schema/allocator/worker impact and running the CodeGraph Light MCP regression suite. Treat daemon, cohort, watcher, installer, updater, UI, hook, and release changes as excluded by default unless the user explicitly expands scope.
- CodeGraph Light stdio MCP must remain process-local and must not bootstrap or depend on the upstream per-account shared daemon. Preserve supervised index workers and cross-process publication locks, but do not reintroduce a shared MCP daemon, daemon version handoff, or cross-session process-lifetime coupling without explicit user approval and a new product-level design review.
- Any change inherited from upstream that affects daemon startup, version cohorts, executable replacement, IPC, or process lifetime must pass a real multi-session Windows handoff regression before deployment or release: keep an old MCP session alive, rename and replace the executable, start a new MCP client against the same cache/runtime within the Codex startup timeout, verify the old session is safely retired or remains serviceable, and verify the new session initializes without requiring every Codex process to restart. Upstream's own tests are not sufficient evidence for this contract.
- Do not infer a CodeGraph Light release version from repository age, absence of local tags, or upstream tags. A release version must be explicitly chosen for this fork after upstream-divergence review, and release publication remains prohibited until the installed canonical path is cold-started and hot-replaced against the real shared cache/runtime.
- Before release, verify concurrent traces against both a synthetic fixture and a private real-world corpus: every request must return a result or structured error without terminating the MCP transport, deliberate fail-stop paths must be diagnosable, and private corpus identifiers must never enter tracked files or public release material.
- Use only synthetic identifiers in tracked tests, fixtures, examples, documentation, commit messages, tags, and release metadata; never reuse names, symbols, paths, or derived project IDs from private reproduction corpora, and block every public push or publication until a bounded scan of the complete reachable history and exact public text finds no non-public identifiers.
